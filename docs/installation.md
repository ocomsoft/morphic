# Installation Guide

This guide covers installing and setting up morphic for Go-based database migration management.

## Prerequisites

- **Go 1.24 or later** — Required to install/build the morphic CLI itself; **not** required at runtime when applying migrations (the Starlark interpreter executes them in-process — see [How migrations run](#how-migrations-run))
- **Git** — For cloning the repository
- **CGO_ENABLED=1** — Required only when using SQLite; PostgreSQL, MySQL, and SQL Server do not need CGO
- **Database** — One of the supported databases: PostgreSQL, MySQL, SQLite, or SQL Server

## How migrations run

`morphic migrate` does **not** invoke `go build`. Each migration `.star` file in your project is loaded by the embedded [Starlark-Go](https://github.com/google/starlark-go) interpreter and executed in the morphic CLI process. Starlark is a deterministic, Python-like language designed for configuration and scripting — migrations generated by `morphic generate` use it transparently.

## Installation Methods

### Option 1: Go Install (Recommended)

```bash
go install github.com/ocomsoft/morphic@latest
```

This places the `morphic` binary in `$(go env GOPATH)/bin`. Ensure that directory is on your `PATH`.

### Option 2: Build from Source

```bash
git clone https://github.com/ocomsoft/morphic.git
cd morphic
go build -o morphic .

# Optionally install globally
sudo cp morphic /usr/local/bin/
```

### Option 3: Download Pre-Built Binary

Download pre-built binaries from the [releases page](https://github.com/ocomsoft/morphic/releases):

```bash
# Linux/macOS
curl -L https://github.com/ocomsoft/morphic/releases/latest/download/morphic-linux-amd64 -o morphic
chmod +x morphic

# Windows
curl -L https://github.com/ocomsoft/morphic/releases/latest/download/morphic-windows-amd64.exe -o morphic.exe
```

## Verification

Confirm the installation is working:

```bash
morphic --help
morphic init --help
```

## Quickstart: Starlark Migration Workflow

This is the primary workflow. Migrations are generated as Starlark source files (`.star`) and applied in-process via the Starlark interpreter — no compile step required at runtime.

### 1. Install

```bash
go install github.com/ocomsoft/morphic@latest
```

### 2. Initialise Your Project

Run `init` from the root of your project. This creates a `migrations/` subdirectory:

```bash
morphic init
```

### 3. Define Your Schema

Edit `schema/schema.star` to describe your database tables and fields:

```python
database(
    name = "myapp",
    version = "1.0.0",
)

table(
    name = "users",
    fields = [
        field(name = "id", type = "uuid", primary_key = True, default = "new_uuid"),
        field(name = "email", type = "varchar", length = 255, nullable = False),
        field(name = "created_at", type = "timestamp", default = "now", auto_create = True),
    ],
)
```

### 4. Generate Your First Migration

```bash
morphic generate --name "initial"
# Creates migrations/0001_initial.star
```

### 5. Apply Migrations

```bash
morphic migrate up
```

This loads every `.star` file in `migrations/` via the Starlark interpreter and runs them in-process. No compile step required.

### 6. Ongoing Workflow

After each change to `schema.star`, regenerate and apply:

```bash
morphic generate
morphic migrate up
```

### Project Layout After Init

```
myapp/
├── go.mod
├── schema/
│   └── schema.star          # Starlark schema definitions
└── migrations/
    └── 0001_initial.star    # generated Starlark migration (after first morphic generate)
```

## Database Configuration

The `morphic` CLI reads connection settings from environment variables.

### PostgreSQL

```bash
export MORPHIC_DB_TYPE=postgresql
export MORPHIC_DB_HOST=localhost
export MORPHIC_DB_PORT=5432
export MORPHIC_DB_USER=postgres
export MORPHIC_DB_PASSWORD=yourpassword
export MORPHIC_DB_NAME=yourdb
export MORPHIC_DB_SSLMODE=disable
```

### MySQL

```bash
export MORPHIC_DB_TYPE=mysql
export MORPHIC_DB_HOST=localhost
export MORPHIC_DB_PORT=3306
export MORPHIC_DB_USER=root
export MORPHIC_DB_PASSWORD=yourpassword
export MORPHIC_DB_NAME=yourdb
```

### SQLite

SQLite requires CGO. Build with `CGO_ENABLED=1`:

```bash
export MORPHIC_DB_TYPE=sqlite
export MORPHIC_DATABASE_URL=./database.db
```

### Development .env File

Create a `.env` file for local development:

```bash
MORPHIC_DB_TYPE=postgresql
MORPHIC_DB_HOST=localhost
MORPHIC_DB_PORT=5432
MORPHIC_DB_USER=dev_user
MORPHIC_DB_PASSWORD=dev_password
MORPHIC_DB_NAME=myapp_development
```

### Production Environment

```bash
MORPHIC_DB_TYPE=postgresql
MORPHIC_DB_HOST=production-db-host
MORPHIC_DB_USER=app_user
MORPHIC_DB_PASSWORD=secure_password
MORPHIC_DB_NAME=myapp_production
```

## Troubleshooting

### "Command not found"

```bash
# Ensure GOPATH/bin is on your PATH
export PATH=$PATH:$(go env GOPATH)/bin

# Or use the full path
./morphic --help
```

### "No schema files found"

```bash
# Check that schema.star exists in the expected location
find . -name "schema.star" -type f

# Verify directory structure
ls -la schema/
```

### Database Connection Issues

```bash
# Check that environment variables are set
echo $MORPHIC_DB_HOST
echo $MORPHIC_DB_USER

# Test a direct connection
psql -h $MORPHIC_DB_HOST -U $MORPHIC_DB_USER -d $MORPHIC_DB_NAME
```

### Schema Parsing Errors

```bash
# Validate your schema file syntax using morphic directly
morphic validate
```

### SQLite: CGO Errors

SQLite requires CGO at the time the morphic CLI binary is built. If you installed morphic via `go install` and SQLite errors appear at runtime, rebuild with CGO enabled:

```bash
CGO_ENABLED=1 go install github.com/ocomsoft/morphic@latest
```

SQLite requires CGO at the time the morphic CLI binary is built. If you installed morphic via `go install` and SQLite errors appear at runtime, rebuild with CGO enabled as shown above.

## Legacy SQL Workflow

For projects using the older YAML-to-SQL+Goose workflow, initialise with:

```bash
morphic init --sql
```

This generates raw `.sql` migration files managed by Goose instead of Starlark source files. See [docs/commands/init.md](commands/init.md) for full details.
