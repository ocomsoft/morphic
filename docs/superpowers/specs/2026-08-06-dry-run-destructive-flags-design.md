# Enhanced --dry-run with Destructive Operation Flagging

**Date:** 2026-08-06
**Status:** Draft

## Purpose

Enhance the `morphic generate --dry-run` flag so that both humans and AI agents
can understand exactly what a migration will do before it is written to disk.
The current `--dry-run` dumps raw migration source; the enhanced version adds a
human-readable change summary with destructive operations clearly flagged, injects
`# DESTRUCTIVE` comments into the migration source, and supports `--json` for
machine-readable output.

## Requirements

1. `--dry-run` prints a change summary **then** the annotated migration source.
2. Destructive operations are flagged in two places:
   - A separate "Destructive Operations" warning section in the summary.
   - `# DESTRUCTIVE: <description>` comments above each destructive operation in
     the `.star` source.
3. `--dry-run` exits with code **1** when any destructive operation is present,
   code **0** otherwise.
4. A new `--json` flag (only valid with `--dry-run`) outputs a structured JSON
   object instead of human-readable text.
5. Documentation updated to describe all new behaviour.

## Human-Readable Output Format

```
Morphic Dry Run: 0003_remove_posts

Changes (4):

  Tables removed (1):                          [DESTRUCTIVE]
    - posts
  Fields added (2):
    - users.phone
    - users.avatar
  Fields removed (1):                          [DESTRUCTIVE]
    - users.old_email

WARNING: 2 destructive operation(s) detected:
  - Remove table "posts"
  - Remove field "users.old_email"

--- Migration Source ---
# Auto-generated by morphic generate
migration(
    name = "0003_remove_posts",
    dependencies = ["0002_add_fields"],
    operations = [
        # DESTRUCTIVE: removes table "posts"
        drop_table("posts"),
        add_field("users", ...),
        add_field("users", ...),
        # DESTRUCTIVE: removes field "users.old_email"
        drop_field("users", "old_email"),
    ],
)
```

```json
  "migration_name": "0003_remove_posts",
  "dependencies": ["0002_add_fields"],

```

## Exit Codes

| Condition | Code |
|-----------|------|
| `--dry-run`, no destructive ops | 0 |
| `--dry-run`, destructive ops present | 1 |
| `--dry-run --json`, no destructive ops | 0 |
| `--dry-run --json`, destructive ops present | 1 |

The exit code applies regardless of output format so CI pipelines can gate on it
without parsing output.

## Implementation Notes

- The `Change.Destructive` bool already exists on every change in the diff — no
  new detection logic needed.
- The generator already has a pattern for injecting comments (`# REVIEW:` for
  review decisions at line 97 of `starlark_generator.go`). The `# DESTRUCTIVE:`
  comment follows the same pattern, keyed off `change.Destructive`.
- The `--json` flag errors if used without `--dry-run`.
- `printChangeList` is enhanced to accept a `showDestructive bool` parameter so it
  can add `[DESTRUCTIVE]` markers in dry-run mode while remaining clean in the
  normal generation flow. A new `printDryRunSummary` function wraps it with the
  destructive warning section and migration source output.
